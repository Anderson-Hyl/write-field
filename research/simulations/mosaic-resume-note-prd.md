## 问题

周五晚上，我停在一个 Mosaic Room：Agent 正在旁边，Diff 与参考网页也还在。周六回来，空间恢复了，但我仍要翻终端和笔记，才记起“昨天为什么没有继续”。

本需求的假设是：**恢复工具所在的位置，还不足以恢复下一步工作的意图。** 如果现有 Note 已经足够方便，这个 feature 就没有必要独立存在。

用户故事：作为在多个开发任务间切换的人，我想主动留下一句下次要做什么，并关联一个已有 tile；再次进入该 Room 时能找到这句话，由我决定是否跳过去。

示例：“下次先比较取消前后的日志；目前只排除了 UI 卡死，还没确定是请求重试。”

## 当前依据与尚未证实之处

| 类型 | 内容 | 对需求的影响 |
| --- | --- | --- |
| 当前实现 / 文档依据 | Mosaic 已有 Note、Room 恢复、聚焦 tile、Jump Palette | 新能力应复用这些，不新做任务管理器 |
| 当前明确约束 | Attention / MRU 是运行时状态，重启不能恢复 waiting | 留言是人写的意图，不能伪装成进程仍在等待 |
| 需求假设 | 人会忘记离开前的下一步，且普通 Note 不够易发现 | 需要真实离开 / 返回经历支持，不能写成已有用户反馈 |
| 作者取舍（本演练） | 每 Room 最多一条当前接续便笺 | 换取低维护成本；不宣称多条不合理 |

本地依据：`README.md` 的 Notes、Rooms、Tiles；`Documentation/Mosaic · Handoff · Attention Layer.md` 的 runtime 边界与重启行为；`MosaicPackage/Sources/MosaicCore/JumpPalette.swift` 的现有目标与目录。它们说明可借的现有能力，不能证明需求成立。

## 目标与非目标

目标是让用户回来时找到自己留下的下一步，并直接到达相关工作对象。评价时要问“是否更快开始有效工作”，不把便笺数量当成成功。

不做自动总结、不监控离开、不恢复历史进程状态、不执行便笺内的命令、不恢复代码 / 文件快照、不成为多任务待办列表。普通 Note 继续可用；本功能无需 AI 才能成立。

## 方案比较与本稿选择

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| 沿用普通 Note | 零新概念，已有自由度 | 回来时可能仍要寻找那张 Note |
| 给现有 Note 标记“下次继续” | 内容仍是 Note，只补发现和关联入口 | 需要定义该标记的唯一性与失效行为 |
| 新建独立 Checkpoint 对象 | 可扩展很多恢复信息 | 容易被理解为快照、回滚或历史管理 |

**本演练选择第二种。** 理由是当前缺口是发现与接续，不是存一份世界快照。每 Room 指定至多一个 Note；可选关联同 Room 的一个目标 tile。名称和长度限制仍待真实使用决定，不强迫作者填写表单。

反方仍然保留：如果把 Note 放在入口附近就能解决问题，“下次继续”标记可能只是一个额外维护动作。

## 主流程

1. 离开前，用户在现有 Note 上选择“设为下次继续”；没有 Note 时可先创建并输入。没有离开拦截弹窗。
2. 用户可明确关联一个同 Room 的 tile，也可只留文字。关联不能因为当前焦点变化而暗中改变。
3. 如果已有接续 Note，提示将替换哪个标记；用户选择后只替换指定关系，旧 Note 内容保留。
4. 再次进入 Room，在稳定入口呈现接续 Note 的短预览。它是入口，不自动打开模态框、不自动抢焦点、不进入 waiting 计数。
5. 用户可以“查看便笺”“前往关联对象”或“取消接续标记”。单纯看过不等于做完，不能自动清除。
6. 用户改变下一步时直接编辑 Note；没有后台 AI 帮忙重新总结。

## 边界行为

| 情况 | 预期 |
| --- | --- |
| 目标 tile 被删除 | 留言保留，显示目标不存在；可重新关联，不猜另一个 tile |
| 目标 tile 移到别的 Room | 本稿选择提示关联已离开本 Room，由用户重新指定；不静默跨房间跳转 |
| Note 被删除或移出 Room | 清除本 Room 的接续指定；不私建内容副本 |
| 取消接续标记 | 只取消指定，保留 Note 与目标 tile |
| 重启应用 | 恢复接续指定和 Note；进程状态按现有运行时机制重新建立 |
| 便笺写着一条 shell 命令 | 只是文本，跳转也不执行命令 |
| 关闭入口预览 | 仅影响本次显示，不等于删除内容或完成工作 |

## 验收例子

- 给 Room A 的 Note N 设置接续并关联 tile T，关闭重开后，在 A 能找到同一句话，点击前往才聚焦 T。
- A 有接续而 B 没有，进入 B 不显示 A 的便笺。
- 删除 T 后，N 仍可读，入口明确告知关联失效，不能跳到同名 tile。
- 将接续从 N 改为 M，N 的正文保持原样；取消 M 的标记也不删 M。
- 打开、关闭或略过接续预览都不增加 waiting 计数，不恢复历史 waiting，不改变终端进程。
- 创建 / 修改接续指定走应用现有可撤销编辑路径；具体数据落点由 Mosaic 工程另议，不在这份 PRD 假装已定。

## 交付前仍要决定

入口是 Room 顶部的小提示还是现有 Jump / Room 菜单，需对照真实返回过程。也需要确认“每 Room 一条”会不会在多 Workspace 房间中太窄。

下一次讨论应带着一段真实离开 / 返回的经历，比较普通 Note 和指定接续 Note 的差异。在这些证据出现前，不把本稿转成开发承诺。
