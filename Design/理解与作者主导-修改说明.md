# HTML 规则审阅与修改 · 2026-09-19

目标：借助 AI，帮助作者真正理解自己写下的内容，让真实的思考与读者产生共鸣。

本轮检查了现有 11 份 HTML 的内容与交互结构，修改 7 份，新增一份共用 CSS。没有改 Swift 工程。上一份 [双场景演练](../research/saturday-writing-walkthrough-v2.md) §五记录的是修改前的板，不能当成修改后的现状。

## 判断

保留中央稿面、周围上下文、四类角色色、作者决定插入、原始资料可追溯、AI 光不落正文。这些规则对作者主导有价值。

本轮补足三件事：理解通过连续讨论形成；作者的取舍应与助手建议分开留下；一次请求的阅读范围要容易理解。没有加入“理解度分数”、强制复述或“答对才准插入”。软件不对作者是否真的理解盖章。

## 提案与定案的边界

- 引用来源门禁、正文不被 AI 自动写入、原始资料与模型解释分开，是既有地板在演示中的修正。
- 空稿 Topic 级讨论、同卡连续追问、作者取舍便笺、按次选择范围、全文请求后回局部，是【待定交互提案】。已回写产品 §14.1 与 AI 语义面 §9.8。尚不授权工程绕过原有锚点规则。
- 插入、部分采用和引用均由作者点击确认；确认用来选择内容和位置，不声称点击等于理解。
- 原型用固定示例，不调模型、不真实抓网页、不自动分析正文。自由问题只被保留，未伪造语义回答。暂离恢复仅在同一页内，刷新不保存。

## 检查结果与限制

对全部 HTML 做了内联 JavaScript 语法、唯一 ID、文件链接检查；使用 jsdom 检查正文不变、取消、选区插入与撤销、无来源引用门禁、脚注去重、后续编辑保护、两篇状态隔离、取舍历史、请求范围与版本快照、键盘选择、模拟刷新保留剪取，以及点按入口。

这些是 DOM 行为检查。此前浏览器安全策略禁止打开本地 HTML，本轮未绕过，也没有声称已完成渲染、真实选区手感、拖动几何、软键盘、真机触控或辅助技术验证。

## 看板建议

先打开“一次写作”，用预设问法走一轮，再用自己的话写两句。接着看“采用与引用”的选区、取消与撤销，最后看“本次阅读范围”中同一次改稿前后的请求记录。要讨论的是这些动作是否帮助理解、是否打断思考；球的材质和卡的位置不作为这一轮的结论。
