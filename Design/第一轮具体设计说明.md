# 第一轮具体设计：在段落旁把一个问题想下去

2026-09-19 · **可交互设计提案，未定案。**

入口：[写作现场 · 段旁讨论](写作现场-设计提案.html)，以及用于对照的 [Mosaic 组件版](写作现场-Mosaic组件版.html)。此前的[双场景流程演练](一次写作.html)保留，用于比较流程；这一轮集中做 Traversable 写作中的几个完整片段，不扩成全套 App。

## 本轮的设计判断

这张界面的工作是：作者写到某一段，能在附近继续讨论、核对资料，并自行决定是否采用内容。最有辨识度的部分应是**正文段落与讨论之间的近距离联系**。纸保持完整，旁边的对象根据当前工作出现；空间不是用来整理卡片的。

旧流程页的信息齐全，但导航、说明、状态和按钮同时占据大量视野，更适合解释规则。新页把这些退到单独的原型条与说明里，直接呈现一个正在写作的现场。没有加人格选择器、理解状态、待完成清单或必须填写的意图表。

先去掉一项：不常驻“我的理解与取舍”输入框。它改成安静的作者笔记入口，作者有想留下的内容再打开。记录不是写作通行证。

## 已做的三个片段

### 1. 就这段继续讨论

- 每段有可以点按和键盘到达的讨论按钮，触控不依赖 hover。展开后显示所针对的原句，点原句回到正文。
- 同一段的追问留在同一张讨论卡中，切换段落保留各自未发送的输入。
- 回复区、追问和本次阅读范围放在一个地方；范围初始为当前段，可明确选全文和指定资料。全文不会变成以后所有请求的默认。
- 输入自由问题只保存问题并说明没有接模型。示例问法会展示标明为示例的答复，不假装分析当前稿。
- 展示中的卡可以取消；作者继续在正文输入不自动取消或触发请求。手动转向另一段讨论会取消尚未完成的示例，原问题保留。
- 改稿后，旧答复显示基于旧版本；展开“本次参考”可看当时记录的文本。
- “关于这篇”支持空稿讨论，不画虚假的段落连线。上方状态选择器可切换空稿与已有草稿，内容分别保留。

这里的段落 ID 只用于 HTML 中已有输入块的归属和布局，不写进导出的 Markdown，也不声称已经实现最终锚点算法。

### 2. 核对手边资料

- 常态只展示资料标题、版本和短签名，避免周围比正文更重。
- 查看时在一个可关闭的短任务窗口里显示完整预置摘录、来源域名和实际读取层次；可在新页面打开原始文档。
- 资料属于本篇参照材料，没有为了视觉效果伪造指向某句话的引用连线。
- 较窄窗口先收掉左侧资料区，顶栏“资料”仍可到达同一个查看界面。
- 这轮没有加入真实网页抓取、脚注创建或可信来源回执。签名明确是预置材料，不能把“看得到出处”当成已验证事实。

### 3. 选择采用，再回到正文

- 从讨论进入一个短的选择面，同时看到解释与代码两个候选块；可只选一块，或两块都选。
- 明确选择插入位置，展开可看 Markdown 预览。只有“插入正文”改变文稿，取消不变。
- 插入后返回写作，定位到新增内容，顶部提供“撤销采用”。可以逐次撤销本页尚未被改写的采用操作。
- 撤销只移除那次新增的块，不恢复整篇快照，所以其它段落后来写的内容不会被覆盖。新增块自身已被作者修改，则保留文字并提示手动处理。
- 普通文字编辑继续使用浏览器自己的撤销；本原型没有模拟完整编辑器的统一撤销栈。重载后不保留“撤销采用”的操作栈。

## 布局与视觉选择

规则不是“所有旁注永远列出来”。宽窗口里，手边资料位于左侧，正在讨论的段落对应右侧一张卡；收起时保留返回入口。讨论的纵向位置跟随目标输入块。正文仍只有一个纵向阅读方向。

```text
宽窗口
  文稿名称                                      资料  只看稿  导出

  手边资料         ┌──────────────────┐
  简短来源卡       │ 标题              │
  作者笔记入口     │                  │
                   │ 当前段落       ◯─┼─ 这段的讨论
                   │                  │  原句 / 往返
                   │ 下一段           │  采用 / 追问
                   └──────────────────┘

较窄窗口：先隐藏左侧资料区，保留顶栏资料入口。
紧凑窗口：完整稿面 → 同一张讨论卡；点段旁按钮到达讨论，点原句返回。
```

紧凑布局是为了不把稿面挤到无法阅读，不是已定的 iPad 竖屏方案。需要你实际使用后再判断是否应改成可收起的浮层。暂不在没有验证的情况下加入第三套导航。

| 设计 token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| 桌面 | `#E9EAEC` | `#202326` | 退后的写作环境 |
| 控件层 | `#F7F7F8` | `#292C30` | 顶栏与原型说明 |
| 旁注 | `#FFFFFF` | `#303439` | 临时内容 |
| 主要文字 | `#25282D` | `#ECEEF0` | 内容与操作 |
| 次要文字 | `#60666E` | `#B1B8C0` | 版本、范围、说明 |
| 操作与助手 | `#28617B` | `#A0C8DB` | 提问、采用和讨论标识 |

资料蓝、作者笔记棕只落在图标和小标题，不填满卡片。颜色之外同时有文字和形状。CSS 变量只是 HTML 原型 token；最终原生实现应映射系统语义颜色与现有主题。

本板稿面保持暖白，深色外观只让桌面与周围退暗。Mosaic 组件版实际试看后采用这一方向；产品文档 §3 已同步，原先的柔和炭纸方案撤下。真机长时间写作仍需复核亮度与眼疲劳，但原生实现不再同时维护两套稿纸颜色。

正文用系统衬线回退栈，默认 17px；标题约 33px；交互系统字体；代码等宽。说明不小于 11px。触控环境提高讨论内容字号；输入与按钮均有键盘焦点。主要控件目标至少 44×44 CSS px；CSS px 只是浏览器预览尺度，不等同于已完成原生 pt / Dynamic Type 验证。

不做纸上的 AI 光效，不添加虚假的窗口红绿灯、不模拟格式检查器。没有自动消失的反馈消息；反馈可手动关闭。少量透明度过渡尊重 Reduce Motion。原版不使用背景模糊；Mosaic 组件版只在顶栏与 sheet 背板使用，正文和旁注内容本身仍有不透明底色。

### Mosaic 组件版：共享组件语法，不共享画布形态

第二个 HTML 保留相同的信息架构和交互，只替换组件语言，以便直接判断“像 Mosaic”是否真的适合写作现场：

- 圆角采用 Mosaic 的 `4 / 6 / 10 / 14` 阶梯；字段和小按钮为 6，卡片与 toast 为 10，浮动按钮和 sheet 为 14。
- 间距采用 `4 / 8 / 12 / 16`，文字层级采用 `11 / 12 / 13 / 16 / 22`；可见控件趋近 28pt，但 iPad 触控区域仍保持至少 44×44。
- hover、pressed 可沿用强调色的 12%、18% 洗色。Mosaic 原始 selected 24% 洗色在写作场景过重；当前讨论改为暖白卡面、38% 的 1px 轻描边，键盘焦点另用清楚的 focus ring。
- 纸与桌面仍来自 WriteField 的暖白/石色主题；工具栏、按钮、分段选择、sheet、toast 采用 Mosaic 的 slate 与 accent 体系。没有引入 Mosaic 的无限画布、tile 或 AppKit 代码。

旁注颜色只按四个稳定角色分配：资料 `#007AFF`、待决 `#C47B17`、助手产出 `#5B7C8A`、张力 `#C4474A`。实际界面以约 58%–62% 的透明度把它们用于 2px 标记、图标、连线和状态点；标题文字统一回到中性灰，卡面保持暖白。第一次静态渲染曾给当前讨论卡叠加 24% 蓝色洗色、2px 蓝色描边和外圈，实际观看时明显抢过稿纸；依据试看反馈，已改为暖白卡面、38% 的 1px 轻描边，并移除外圈。选中与角色仍由形状、位置、标签和“已连接”状态共同表达。

## Apple design skill 如何影响这一版

使用用户指定的第三方 [SKILL.md](https://github.com/dickwu/apple-design-skill/blob/main/SKILL.md)，按其索引阅读 accessibility、layout、typography、color、macOS、iPadOS、buttons、modality、undo-and-redo、focus-and-selection、generative-ai 的相关章节。它是参考，不是苹果背书；与本产品边界冲突时仍以产品目的和用户指示为准。

| 参考文件与章节 | 本板采取的具体处理 |
| --- | --- |
| `accessibility.md › Mobility`："Offer alternatives to gestures." | 段旁点按入口与键盘等价，不能只靠拖线；颜色不承担唯一含义。[来源](https://developer.apple.com/design/human-interface-guidelines/accessibility) |
| `layout.md › Tablet (iPadOS)` | 窗口变窄时先退让第三层信息，保留稿面宽度；再切换紧凑排列。[来源](https://developer.apple.com/design/human-interface-guidelines/layout) |
| `typography.md › Conveying hierarchy`、`color.md › Inclusive color` | 用字号、留白与角色标签区分内容；测量实际颜色，不用肉眼推断对比度。[文字](https://developer.apple.com/design/human-interface-guidelines/typography)、[颜色](https://developer.apple.com/design/human-interface-guidelines/color) |
| `modality.md › Best practices`："Present content modally only when there’s a clear benefit." | 讨论非模态驻留；资料放大、采用选择、作者笔记各是一个可取消的短任务，不叠加窗口。[来源](https://developer.apple.com/design/human-interface-guidelines/modality) |
| `undo-and-redo.md › Best practices` | 撤销说明针对“采用”，不悄悄撤掉别处新编辑；真正的统一撤销留给编辑器内核。[来源](https://developer.apple.com/design/human-interface-guidelines/undo-and-redo) |
| `generative-ai.md › Transparency / Outputs` | 示例明确标记，取消、范围、旧版本可见；没有模型时不编造自由问答。[来源](https://developer.apple.com/design/human-interface-guidelines/generative-ai) |
| `focus-and-selection.md › Best practices` | 展示答复不抢正文焦点；手动打开/关闭查看面回到原触发位置。[来源](https://developer.apple.com/design/human-interface-guidelines/focus-and-selection) |

旁注的具体宽度、作者笔记由表单改为自选入口、采用面展示两块候选，属于本轮设计判断，不宣称是 HIG 强制要求。

## 已检查与仍需看效果的部分

本轮代码与 DOM 检查覆盖：未发送输入保留、自由输入不伪造答复、取消阻止迟到结果、正文变化与历史快照、采用前预览/取消、部分采用、撤销保护其它编辑、已改写内容不被覆盖、IME marked text 不保存、空稿/已有稿隔离、浏览器重载保留、按钮可访问名称等。

主要文本配色计算结果：浅色正文 14.79:1，次要文字对纸 5.80:1 / 对桌面 4.82:1，操作色对纸 6.80:1；深色文字对旁注 10.77:1，次要文字 6.26:1，操作色 7.03:1。未将这些数值当作全界面可访问性认证。

**尚未完成真机视觉验收。** 浏览器工具对本地 `file://` 页面仍返回 URL policy 阻止；本轮未绕过，也未用本地服务代替。Mosaic 组件版用 macOS Quick Look 做了静态壳层截图，检查了暗色工具栏、稿面、选中讨论卡和张力卡的视觉权重；Quick Look 没有可靠执行页面脚本，不能据此验证动态段落和几何。尚未完成缩放 200%、软键盘或 VoiceOver 实测。响应式与 reduced-motion 目前是实现待查看，不能写成真机测试已通过。

持久化使用本页独立的 localStorage key，与旧板及 App 数据无关；失败时显示“仅本页暂存”，并可导出 Markdown。没有联网发送、模型接入、真实检索或 App 代码变更。此持久化只是让设计体验不会随刷新丢失，不替代 SQLiteData 的技术方案。

下一轮看效果时，优先讨论：卡片与段落是否足够近；讨论是否挤占阅读；“选择采用”是否多了一层不必要的操作；较窄窗口是否仍容易回到原句。**这些措施是否好用可以讨论，作者是否真正理解不作为通过标准。**
